# Phase 8A · HTTP 发信的持久化幂等基础

本阶段交付内部入队能力，尚未开放 HTTP 发信接口。7B 自动退信仍缺可信来源验证，保持待查；8A 可独立推进，不把未知来源的退信接入自动抑制。

## 已实现

新增 `message.Postgres.EnqueueIdempotent` 与迁移 00012。调用方提供已校验、已落盘的 Submission、稳定的 API key 记录 ID 和幂等键；该方法不承担身份认证、发件权限或原文校验，不能直接接受来自 HTTP 客户端的 Submission 或摘要。

SMTP 与 API 共用 `enqueueTx`，在同一事务写消息、收件人、入队事件，执行 suppression 检查并通知队列。SMTP 入口行为保持；API 记录的 source_type/event source 为 api，只关联 api_key_id，不冒用 SMTP 账号。

## 幂等契约

- 范围为 API key 记录 ID，同一个字符串在不同 API 身份下独立。凭证轮换若保留该记录 ID，则保留幂等范围；更换记录 ID 是新的范围。
- 幂等键为 1–128 字节可打印 ASCII，不含空格；数据库只保存其 SHA-256，不保存原键。调用者宜使用随机键；摘要存储不使低熵值不可猜测。
- 请求指纹由版本 1、完整原文 SHA-256/字节数、信封发件地址及有序收件地址列表组成，以固定结构 JSON 编码后计算 SHA-256。地址限定为既有 ASCII 单邮箱规则。
- 原文字节、发件地址、收件人内容或顺序发生变化均视为不同请求；不折叠别名、local-part 大小写或重排收件人。路径、时间、生成的 Gateway ID 和派生头字段不属于请求身份。
- 同一身份、同一键、同一指纹返回已提交消息的原 ID，`replayed=true`；不同指纹返回 `ErrIdempotencyConflict`。首次成功返回新 ID，`replayed=false`。
- 并发竞争通过唯一键和事务处理，不依赖进程内互斥。重放不会重建收件人、事件、抑制决定或队列通知，也不会重置已接受/UNKNOWN 等已有状态。
- 成功只代表可靠入队记录，不代表发信或入箱；全部收件人被抑制时，消息可直接处于 SUPPRESSED。

## 事务与保存责任

`api_submission_ledger` 的主键为 `(api_key_id,key_sha256)`，绑定请求摘要和唯一消息 ID。对消息的外键在事务提交时验证，从而允许先争取幂等键，再写消息；事务同步提交后才确认成功。

入队事件、抑制检查或最终提交失败会回滚本次幂等记录。网络造成提交结果不确定时继续返回错误，调用方以后必须使用相同键与相同请求重试，不能换键。重试若读到已提交记录则返回原 ID；若原事务回滚则可以重新创建。

此方法接收已存档的 Submission，不能解决接收 HTTP 请求时的资源准入或重复请求所产生的候选存档。未来接入层必须限额读取、计算服务端摘要、核验权限，并处理明确未引用存档的回收。提交结果不明时不能删除原件。本阶段集成测试的额外文件仅存于自动清理的测试目录，不据此宣称生产重复请求没有磁盘成本。

幂等记录追加后不可更新或删除，没有 TTL。绑定的消息不能被普通删除；未来保留和清理方案必须显式处理幂等窗口或保留不可重放的历史标记，不能静默释放旧键。

## 后续 Phase 8B / 8C

**8B：认证与有界 HTTP 接入。** 设计独立 API 凭证的创建、吊销、轮换及发件权限；每次请求包括重放都必须重新认证授权。选定流式原文和信封传输格式，限制正文、收件人、连接、每身份速率及并发，复用 Receiver 的头验证与存储边界。管理令牌和 SMTP 密码不能充当发信 API key。默认不开启接口。

**8C：公开接口全链路验收。** 覆盖客户端重试、响应丢失、取消、存储失败、凭证撤销、跨身份隔离、资源满额及重复请求文件回收；校验 raw EML、suppression、Provider 配额和 worker 语义。完成这些验收后才对外宣布 Phase 8 HTTP 发信可用。

## 验收

- 请求指纹测试：内容/信封变化产生不同指纹，存档路径和派生信息不影响指纹，非法地址被拒绝。
- PostgreSQL 并发：8 个相同请求只创建一封邮件、一套收件人和入队事件；所有结果返回同一 ID。
- Fake SMTP：API 入队通过现有 worker 投递，原始 MIME 不变；SMTP 接受后重放不增加尝试。
- 同键不同内容/收件人被拒绝，不同 API 身份可以使用同一个键。
- 事件写入失败和延迟约束触发的最终 commit failure 均回滚消息、收件人、事件和幂等记录；恢复后可重试。
- API 入队保留 suppression；UNKNOWN 后重放保留 UNKNOWN 和原投递次数；数据库拒绝删除幂等历史。

本阶段不创建真实 API 凭证，不连接真实 Provider，也不发送外部邮件。
