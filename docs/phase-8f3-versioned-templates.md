# Phase 8F.3 · 固定版本模板与变量校验

2026-10-08。本阶段提供逐网站凭证的启动配置模板目录，以及 JSON 发信的显式版本引用。模板不参与 worker 重试；提交时固定完整 EML，继续使用现有幂等、队列、配额、状态查询、Webhook 与沙箱。无数据库迁移。

## 管理员发布

在每个 SEND_API_KEYS 身份的 templates 数组中配置模板；目录不跨身份共享。每身份最多八个版本，同 ID 可有多个版本。仍受整份 SEND_API_KEYS 64 KiB 配置上限约束；配置通过现有启动配置渠道载入，需要重启。网站不能在请求中定义或发布模板。

先准备不含 version 的本地文件：

```json
{
  "id": "order",
  "subject": "订单 {{number}}",
  "text": "订单 {{number}} 已确认。",
  "html": "<p>订单 {{number}} 已确认。</p>",
  "variables": ["number"]
}
```

使用仓库示例工具验证并生成版本：

```sh
go run ./examples/template-version < order-template.json > order-template-versioned.json
```

工具只读本地输入、生成配置，不连接服务或发布。将生成的完整对象加入对应身份的 templates 数组，保留该身份既有凭证与策略，通过既有部署流程重启服务。此示例版本为 `35a7b10310bd22595df15dd4f72416e91a78217e699d890f99b5bc6cdb4e5b23`。

version 必须为计算所得内容摘要，启动时复核，不能把新正文写进旧版本。修改后生成新对象并追加；保留网站仍可能重试的版本，没有 latest 或隐式默认版本。目录上限包含历史版本，移除前应先协调客户端停止引用。移除版本后的 HTTP 重放仍需要渲染，因此会返回 400，即使同键曾被接受；客户端此时应查询原消息结果，不换幂等键补发。已入队任务不依赖目录，继续发送原存档。

摘要算法固定命名空间 `relaytale.template.v1` 加一个零字节，其后依次写 ID、Subject、Text、HTML、排序后的 Variables 名称。每个字段以 UTF-8 字节长度的八字节无符号大端整数前缀编码，最后取 SHA-256 小写十六进制。Version 字段本身不参与摘要；变量声明的排列顺序不改变版本。无需自行实现算法，推荐使用示例工具。

## 网站提交

同一个 POST /v1/messages，保持 8F.1 的身份、信封与幂等头：

```json
{
  "date": "2026-10-08T12:00:00Z",
  "template": {
    "id": "order",
    "version": "35a7b10310bd22595df15dd4f72416e91a78217e699d890f99b5bc6cdb4e5b23",
    "variables": {"number": "ORDER-42"}
  }
}
```

模板模式不能同时提交 subject、text 或 html，即使值为空也拒绝。from_name、reply_to、attachments、业务头、消息流与期限仍可使用；附件继续遵守 8F.2 上限。没有 template 的既有 JSON 和原始 EML 保持兼容。模板模式使用 json-v3；无模板继续保持 json-v1/v2 固定字节摘要。

模板 ID 和变量名是 `[a-z][a-z0-9_]{0,31}`。每模板最多 16 个声明变量，必须全部在主题/正文中使用；所有占位符必须有声明。唯一语法为精确 `{{name}}`，不接受函数、循环、条件、导入、模板定义或其他 Go 模板语法。主题源最多 256 字节，text/html 各最多 16 KiB，至少一个正文非空。模板源是管理员控制的邮件内容，不提供恶意静态 HTML 净化或病毒扫描。

请求 variables 必须是对象，名称恰好等于声明集，值只能是字符串；每值最多 1024 UTF-8 字节，所有值合计最多 8192 字节。缺失、多余、重复、null、数组、嵌套值和未知字段拒绝。插入值只替换一次，不把变量里的 `{{...}}` 再当模板执行。

文本与主题进行有界替换，主题渲染后再次拒绝控制字符及超过 256 字节的结果。HTML 使用 Go html/template 的上下文转义，变量保持字符串，不转换为受信 HTML/URL。危险 URL 产生的拒绝标记会使提交失败，不能当作链接正常发送。渲染输出 text/html 各最多 16 KiB；写入器在展开过程中限制输出，不先创建无界字符串。完整 JSON 请求仍最多 32 KiB，完整 EML 仍受部署大小上限限制。JSON 解码和渲染在既有资源预算到位后执行，无网络抓取或代码执行。

无权限目录中的 ID/版本、错误变量、渲染失败统一返回 400 invalid_json_message，不通过错误区别是否属于另一个网站；请求/EML 超限为 413。新版本、变量内容或附件变更参与幂等，重复使用原键会冲突。

## 固定证据与范围

构建摘要包含模板 ID、明确版本、规范化变量与最终内容；EML 记录 X-RelayTale-Template 和 X-RelayTale-Template-Version，稳定 Message-ID 及存档指纹固定该次提交。变量不会单独写入审计、状态查询或 Webhook，仍作为邮件正文受现有存档保护。启动审计只记录所发布的 ID/版本，不记录模板正文或请求变量。

尚未提供数据库模板目录、动态管理 API、语言回退、预览界面和工作台发布；预览可先向既有沙箱身份配置目录并提交，使用 MIME 检查验证输出。HTML 上下文转义不代表收件客户端不会执行静态 HTML 或加载外部资源。未来渲染器版本升级应保持固定字节兼容，不能静默改变同版本请求。

## 验收

完整隔离镜像 `make ci` 通过：格式检查、go vet、构建与全仓库 race 测试；PostgreSQL 集成测试耗时 247.005 秒。先行模板/JSON 定向数据库回归也通过（6.412 秒）。仅使用隔离数据库与 Fake SMTP，不发送真实邮件。

新增测试覆盖旧版本内容不可替换、新版本发布后的旧键重放、版本变化冲突、目录移除后原队列仍投递原存档、网站范围隔离、沙箱零出站与审计正文/变量不泄漏。单元测试覆盖受限语法、缺失/多余/重复变量、HTML/URL 上下文转义、展开预算、并发共享渲染和 json-v3 固定字节摘要；既有 json-v1/v2 摘要继续通过。macOS 下模板/JSON race 检查通过（1.366 秒），Linux 完整回归包含最终并发及摘要测试。

版本生成工具已实际验证本文示例摘要。OpenAPI JSON 及本地引用、暂存 diff 检查和 Gitleaks 秘密扫描通过。工作区已忽略的临时目录不在测试镜像及本阶段提交中，未改动前阶段记录的未格式化临时文件；本阶段所有 Go 文件格式均通过。
