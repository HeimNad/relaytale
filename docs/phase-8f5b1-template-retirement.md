# Phase 8F.5b.1 · 模板版本退役

2026-10-08。本阶段先落实持久模板的不可逆退役与有界历史，为后续草稿和工作台管理提供明确生命周期。没有新增 HTTP 管理权限或浏览器界面。

## 操作与生效边界

使用运营数据库凭证执行：

```sh
relaytale retire-template --api-key-id WEBSITE_CREDENTIAL_UUID \
  --id notice --version EXACT_CONTENT_VERSION \
  --actor operator_name --reason 'caller retry window ended'
relaytale list-templates --api-key-id WEBSITE_CREDENTIAL_UUID
```

必须指定网站身份、模板 ID 和完整版本，不能用 latest。操作者和原因必填、有界且拒绝控制字符；这些标签用于审计，不替代凭证授权。可以退役已禁用身份的模板，不能操作另一身份的版本。首次操作在身份锁下原子提交 TEMPLATE_RETIRED 审计与退役记录；提交失败不报告成功。同一版本重复操作返回 replayed，不追加历史。错误后只能重试同一目标并查询元数据确认。

**退役需在业务网站的请求重试窗口结束后执行。** 重启后版本不再参与渲染，旧请求即使带原幂等键也会因模板不可用而拒绝，不会新增邮件。已接受消息的状态查询与回调继续使用既有接口；已入队 EML、投递重试正文不会重建。如果需要立即阻止网站提交，使用既有身份禁用流程，不能依赖退役命令即时生效。

退役不热更新进程：现有进程保留已编译快照；启用 use_published_templates 的新进程才会排除退役版本。不允许在同一身份静态目录中配置一个已退役的持久版本来绕过排除，冲突会阻止启动。use_published_templates=false 仍使用独立静态配置目录，持久退役并非覆盖所有配置来源的全局禁止策略。

退役不可撤销，不删除定义、发布审计或退役证据。再次发布相同内容仅确认原发布记录，不能复活版本；确需替换时发布新的内容版本。目录列表增加 retired_at，仍只提供元数据，不输出模板正文。

## 容量与验证

每身份活跃持久目录最多八个版本、64 KiB；合并静态目录后仍最多八个版本。每身份全部持久历史最多 64 个版本、512 KiB，退役可释放活跃槽位，但不会释放历史上限。一次启动加载的活跃持久定义总预算仍为 64 KiB。历史满后需后续明确归档方案，不能直接删表绕过。

新增 00026_template_retirement.sql，退役表外键关联原版本与独立审计，数据库触发器拒绝 UPDATE/DELETE；降级必须有显式计划。启动校验包括已退役定义、原发布审计和退役审计关联，伪造退役不会被静默跳过。备份恢复保留并验证全部历史及活跃限额；不把退役当作投递失败或 suppression。

升级需按 9B.1 停止写入并显式离线迁移，再按 9B.3 重新授予运行账户新表权限；新旧二进制不同时运行。旧 schema 备份使用匹配版本恢复后再升级。未迁移真实部署数据库。

## 验收

完整容器 make ci 通过：格式检查、go vet、构建、全量竞态测试与隔离 PostgreSQL 集成回归（236.982 秒）。定向集成回归通过（9.136 秒），覆盖并发退役去重、审计失败回滚、伪造退役拒绝、旧进程快照/重启排除、静态目录冲突、活跃槽位释放、64 个历史版本上限、受限数据库账户和真实 pg_dump/pg_restore 恢复。

初次定向测试发现：退役并重启后，原请求无法再渲染，因此旧幂等请求也会拒绝。未改变入口和幂等实现来绕过模板策略；增加明确拒绝且不重复入队的回归断言，并要求运营等待业务重试窗口结束。已入队邮件的 Fake SMTP 投递继续成功。

本机 API/CLI 测试及暂存差异检查通过；用户原有 .gitignore 修改保持未暂存。仅隔离 PostgreSQL 与 Fake SMTP，无真实邮件投递，未迁移实际部署数据库。
