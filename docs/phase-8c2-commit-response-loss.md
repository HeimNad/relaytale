# Phase 8C.2：数据库提交确认丢失

本阶段验证 PostgreSQL 已提交、应用却收到连接错误的情况。不改变生产代码、原文保留策略或默认关闭的 HTTP 接入设置。

## 注入方法

测试使用独立 Compose PostgreSQL。仅测试连接池安装 `net.Conn` 包装器，逐帧转发真实 PostgreSQL 响应；启动凭证注册完成后才启用一次性故障。

包装器等待真实服务器的 `CommandComplete(COMMIT)`，在交给 pgx 之前关闭连接并返回 `UnexpectedEOF`。因此数据库已执行提交，而驱动没有收到成功确认。此方法与直接返回一个假的 Commit 错误、或者用约束触发器使事务回滚不同。

包装器仅用于隔离测试的明文 PostgreSQL 连接；生产数据库配置不变。它覆盖应用与驱动在成功确认不可见时的行为，不代表已覆盖 TLS、代理、数据库重启、主从切换及网络分区的全部组合。

## 验收断言

- 第一次 HTTP 请求返回 503，不误报可靠接收。
- 确认成功帧确实被拦截；另一条未修改的数据库连接可读取已提交的幂等记录与消息。
- 原文仍存在，资源预算与临时快照已释放。
- 同身份、同键、同内容重试返回 202、原消息 ID 与 `replayed=true`。
- 重试不发布第二个原文；队列 worker 可投递该消息，只有一次 attempt。

测试位于 `tests/integration/http_commit_response_test.go`。全部发送使用 Fake SMTP，不连接真实邮件 Provider。

## 剩余范围

8C.1 的明确回滚保留测试与本阶段的真实提交保留测试，共同说明：数据库返回错误本身不足以授权删除原文。候选存档识别、安全回收及生命周期管理仍待实现，完整 8C 不因本测试通过而核销。
