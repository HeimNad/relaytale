# Phase 8C.1：HTTP 提交故障验收

本阶段增加故障回归，不改变 HTTP 接口、默认启用状态或投递决策。完整 Phase 8C 尚未完成；自动孤立存档回收不在本次实现范围。

## 验证场景

| 故障 | 注入位置 | 必须保持的行为 |
| --- | --- | --- |
| 响应全部丢失 | 本地真实 HTTP 连接，处理器提交完成后关闭 socket，不发送响应 | 客户端收到连接错误；同键同内容重试返回原 ID、replayed=true；仅一条消息、一个原文文件和一次投递 attempt |
| 上传中断 | 请求体 pipe 在部分正文后返回 UnexpectedEOF | 503、无幂等记录、无原文发布；释放资源和快照；同键重试成功 |
| 落盘后取消 | LocalStore.Save 成功后取消请求 context | 503、无消息与幂等记录；保留已发布原文；释放资源和键锁，重试成功 |
| COMMIT 失败 | 当前 API 身份专用的延迟约束触发器 | 503、事务回滚；保留已发布原文；去除注入故障后同键重试成功 |

测试文件：`tests/integration/http_submission_fault_test.go`。测试使用隔离 PostgreSQL、临时存档及 Fake SMTP，不向真实邮箱发送。

## 保留与回收边界

瞬态上传快照采用 open-unlink，正常结束与错误结束均释放资源。发布前的中断不得产生最终 EML。

最终 EML 一旦发布，目前所有数据库失败路径都保留它，包括测试能确认回滚的情况。测试中取消或提交失败后重试会留下两个文件，但只有重试成功的一个关联队列消息。这是明确保留的运维成本，不应描述为已实现孤立文件回收。

不得仅凭“当前查不到 messages 行”就删除原文：查询失败、未结束的事务或提交结果不确定，都不足以证明文件可删除。后续候选清单和回收必须处理进行中的请求、事务结果、引用关系、并发隔离与审计，并保留 UNKNOWN 证据。通用保留期、磁盘配额与历史回收继续由 Phase 9 统筹。

本次 COMMIT 故障是数据库明确回滚的合成用例，不等同于服务器提交成功但数据库提交响应丢失；后者由后续 [8C.2 连接故障测试](phase-8c2-commit-response-loss.md) 单独覆盖。本地 HTTP 响应丢失测试也不代表已验收所有反向代理行为。

直接扫描整个本地目录的格式脚本会报告被 Git 忽略的 `temp/explain-validation/main.go`；该临时文件不属于本次提交，未修改。隔离构建按 `.dockerignore` 排除 temp，CI 的仓库源码格式检查通过。
