# Phase 8G.1：定时准入与发送门闩

2026-10-08。网站可指定邮件的最早发送时间；先完成不可改写排期、准入容量、幂等与发送边界，再在 8G.2 实现取消。此阶段不提供取消、改期或替换接口，不承诺准点到达或撤回邮件。

## 网站契约

`POST /v1/messages` 可增加一个 `X-RelayTale-Schedule-At`，原始 EML 与 JSON 构建入口共用。格式为带时区 RFC3339、整秒时间，例如 `2026-10-09T16:00:00Z`；实际使用应换成当前未来时间。空值、重复头、无时区与非整秒拒绝 400 invalid_schedule。缺省保留立即可投递语义，SMTP 接入不读取 MIME 中的同名字段。

新请求在数据库网站身份锁内使用当前数据库时钟检查：时间必须在未来且不超过 720 小时；若设置 expires_at，必须严格晚于 schedule_at。不符合返回 422 schedule_out_of_range（期限自身已过或超出范围仍沿用期限错误）。等待准入锁期间已经跨过时间也拒绝，不使用事务开始时间放行。通过准入后若存档期间到点，仍可可靠接受并成为到期可领取任务。

每个网站的未来生产队列最多 100 封、EML 合计 128 MiB。计入尚未到点且状态为 QUEUED/TEMP_FAILED/PARTIAL_ACCEPTED/SENDING/DELIVERY_UNKNOWN 的邮件，身份锁串行化检查至存档发布与提交；两个请求不能同时拿到最后一个名额。超额返回 429 schedule_capacity_exhausted 与 Retry-After:60。重放不占新名额，立即提交不使用未来排期预算。常规网站/消息流提交预算仍在接受时扣除，Provider 尝试额度只在真正领取时预留。此限额是未来队列的逻辑容量，不是全局磁盘配额；已完成存档继续遵守既有生命周期规则。

明确的 schedule_at 规范为 UTC，参与内部 v5 幂等指纹，连同有效期、业务字段、流及原 MIME 摘要固定。不设置排期保留原 v1–v4 指纹。相同时刻的不同时区写法等价；同键改期返回 409。已经提交的同键同内容请求在到点之后仍可重放，不能借此改期或延长有效期。

排期不改变原始 EML、Message-ID、模板版本或确定性 JSON MIME。数据库保护 schedule_at 与网站归属不可改写，并约束排期早于期限。

## 领取与 DATA 边界

next_attempt_at 初始不早于排期；公平领取查询和领取更新各自检查不可改写 schedule_at。因此调整重试时间、重启或恢复不能让未来排期提前领取，尚未到点不建立 SMTP attempt，也不预留 Provider 尝试额度。重试仍受原投递决策约束，排期不解除 UNKNOWN 暂停。

数据库触发器拒绝未来排期进入 SENDING，并在 INSERT/UPDATE 时拒绝提前 data_armed_at。实际 DATA 授权仍经过既有消息租约、抑制与有效期门闩；排期表示最早可开始尝试/授权，不保证网络 DATA、Provider 接受或入箱发生在某个指定时刻。到点后仍可能因停机、Provider、预算或排队等待而延后。

单封网站状态查询返回 `X-RelayTale-Schedule-At` UTC 响应头，v1/v2 JSON 形状保持；状态仍可为 QUEUED，网站应结合排期判断等待原因。MESSAGE_RECEIVED 的内部事件记录排期，管理消息详情展示最早发送时间；既有事务通知语义保持。WORKER_COUNT=0 时仍只接收，不自动投递。

队列年龄指标仅计算已经到点的 QUEUED 邮件；排期邮件的等待年龄从 schedule_at 开始，立即邮件仍从 created_at 开始。尚未到点的等待不会触发积压年龄告警；聚合状态计数仍包含它们，不隐藏存储占用。

新增 00028_message_schedule.sql，旧记录排期为空。按既有停写、显式离线迁移和 schema 启动检查升级，不支持自动降级删除排期证据。无新表或依赖；已有表级运行账户授权覆盖新增列。备份保留排期；恢复校验拒绝 DATA 授权时间早于排期的矛盾记录。恢复仍需核对外部副作用并人工解除启动阻断。

本阶段只迁移隔离测试数据库，未修改实际部署、未发送真实邮件。
