# 网站投递结果：状态查询与 Webhook（8D.1–8D.2 已实现，可信退信关联待完成）

用户已选择同时提供网站状态查询和 Webhook。目标是让网站接收并处理邮件投递结果，不再要求操作者人工翻阅 Provider 收件箱里的 Delivery Status Notification。9A 备份恢复、8D.1 状态查询及 8D.2 签名 Webhook 已完成本地验收；不等待整个 Phase 9 结束。关联 ID、消息流、有效期和沙箱等相邻需求见 [业务网站能力规划](business-website-capabilities.md)，不会全部塞入 8D。

## 返回什么

现有 POST /v1/messages 返回 202、Gateway message_id 和 GATEWAY_ACCEPTED。保留此持久化入队语义，不让请求一直等待最终退信。后续查询与通知按收件人提供：

- 网关已接受、等待投递。
- Provider SMTP 接受：只说明提交给 Provider 成功。
- 临时失败或永久拒绝：包含协议阶段、SMTP 数字码、增强状态码（若有）和经过脱敏的说明。
- DELIVERY_UNKNOWN：不能确认是否已接受，保持人工处置边界。
- 收到待核验反馈：明确标记未验证，不冒充已确认退信。
- 已验证的异步退信：与原 message、attempt、provider、recipient 唯一关联后，作为独立事实展示，不抹去先前 SMTP 接受事件。

不从没有退信推断送达，不从 SMTP 250 推断进入收件箱。内部错误、SMTP AUTH、Provider 凭证、完整会话、其他网站的消息和原始退信 MIME 不直接透出。

## 8D.1：网站身份范围内的状态查询（已实现）

新增发信 API 身份所属消息的只读查询；不把管理 API 的全局权限给网站。按稳定 API 身份授权，令牌轮换不丢失历史访问范围，撤销后拒绝新请求，已取得数据库快照的在途请求可以完成。不同身份访问同一 message_id 不泄漏对象是否存在。

响应同时提供最新摘要与有界事件列表，保留事件 ID、时间、收件人和受限来源分类。当前反馈统一标记 NOT_EXPOSED，不返回全局未验证反馈。接口契约、分页限制及验收见 [8D.1 实现说明](phase-8d1-message-status.md)。客户通过原 message_id 或原幂等请求恢复关联，不另发邮件获取状态。

SMTP 提交的网站另行设计账号范围查询授权和 Gateway ID 获取方式，不能默认复用 SMTP 密码授予 HTTP 管理权限。第一版明确以已有 HTTP 发信 API 身份为范围。

## 8D.2：签名 Webhook 与持久化通知队列（已实现）

配置、接收端验签/去重、暂停与重放以及故障验收见 [8D.2 实现说明](phase-8d2-webhooks.md)。当前发送的是固定公开事件提示，网站查询最新逐收件人状态；不输出未验证 DSN。

目标地址由部署管理员为网站身份配置，默认关闭；发信请求不能随意提供回调 URL。实现 HTTPS、SSRF/地址解析与重绑定防护、禁止重定向、请求/响应大小和耗时限制。

邮件事实与通知 outbox 在同一事务记录。通知事件带稳定 event_id、schema_version、message_id、收件人、事实时间和序号；HMAC 签名覆盖时间戳和精确请求字节，支持密钥轮换。网站验证签名/时间窗口并按 event_id 去重。

通知采用至少一次交付：有界退避、重试预算、暂停/死信与人工重放。超时或网站故障只重试相同通知，不改变邮件状态、不重新投递邮件。网站处理重复、乱序、暂时断线，可通过查询补齐。不得承诺通知 exactly-once。

## 7B 衔接：收件箱退信入口

既有只读 IMAP 收集、原始反馈留存、格式说明及候选查询可以复用。目前这些记录仍为未验证事实，不能因为是从自有收件箱读取就认定来自 Provider；邮件标题与 From 地址也不是来源认证。

Provider 原生可验证事件接口若可用，优先对接；否则对收件箱 DSN 独立验收来源、账号归属与原投递关联。Message-ID 可能缺失、重复或被改写；不得通过主题猜测唯一关系。证据不足时网站只能收到“反馈待核验”，不能自动触发网站的永久封禁、自动重发或系统 suppression。

## 验收

覆盖跨身份访问、撤销/轮换、部分收件人成功、同步 4xx/5xx、final response 丢失、重复和乱序通知、通知提交/确认丢失、签名篡改/重放、SSRF、网站持续失败、进程重启，以及伪造/重复/歧义 DSN。

集成测试使用隔离数据库、Fake SMTP、Fake IMAP 和本机回调接收器。真实网站回调及外部发信按明确目标、数量和范围另行验收。

## 已实现的人工退信反馈（7B.7）

通过管理员显式关联和核验，将待核验、人工确认失败、撤回和冲突结果公开给原业务网站。网站使用 `/v1/messages/{id}/feedback` 查询，监听 `FEEDBACK_LINKED`、`FEEDBACK_REVIEWED`、`FEEDBACK_INVALIDATED` 后重读最新状态。来源始终 UNVERIFIED；现有 v1/v2 SMTP 状态响应保持兼容。详情与升级、容量及保留边界见 [7B.7 手册](phase-7b7-manual-feedback.md)。
