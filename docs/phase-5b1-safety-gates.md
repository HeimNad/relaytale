# Phase 5B.1 · 安全门禁

本阶段在管理 API 前补齐审计指出的流程与认证入口缺口，保持现有保守投递语义，不引入自动重发或原文修改。

## 交付

- GitHub Actions 使用固定提交版本的官方 checkout/setup-go，最小只读仓库权限；独立 PostgreSQL 运行全仓库格式、vet、build、race 检查。集成测试缺数据库明确失败。
- SMTP 连接和来源状态有界；IPv4 /32、IPv6 /64 来源限速；单来源只能占一个 AUTH 并发槽，全局默认两个 Argon2 槽及显式预算；会话绝对时长限制。
- Compose 增加容器内存、CPU 与 Go 软内存目标；工作预算、认证预算分开说明。
- metrics 支持可选 Bearer 验证，未授权请求在数据库查询之前拒绝。
- `preflight-eml` 流式、只读检查待处理存档，提供分页 JSON、完成标志和明确失败退出码。
- 修正历史 receive_test.go 格式遗漏。没有新增数据库迁移。

## 验证

Linux Docker 中执行 `make ci`：全仓库格式、go vet、go build 与完整 PostgreSQL 竞态测试通过。测试包括来源桶、状态表上限、会话期限、真实 TLS SMTP 的多来源认证隔离，以及历史存档的非规范 CR、损坏、缺失和路径越界；预检前后原文、事件、attempt 和队列状态不变。

预检 CLI 在隔离数据库中验证了完整 JSON 输出；Compose 解析验证默认硬内存 512 MiB、CPU 2 和 Go 软目标 384 MiB（不等于已完成该限制下的压力验收）。公开发布前扫描全部 13 个历史提交及本阶段暂存补丁，未发现秘密；扫描不能证明绝对不存在泄漏。

另行验证两项负向门禁：构造格式错误时格式检查失败；强制集成模式移除数据库配置时测试失败。Linux 多来源协议测试依赖 127.0.0.2/3 地址，macOS 跳过该项，因此以 Linux CI 为验收环境。持续负载测试是显式开启的独立测试，不包含在每次 CI 中。

## 边界

来源隔离限制单个来源占满所有认证槽，不承诺分布式攻击下的可用性；NAT 和代理共享来源额度。KDF 活跃工作预算不等于进程 RSS。认证计算不能中途取消。指标令牌默认空，网络隔离仍有必要。

预检仅覆盖指定状态及扫描时可见数据，发现问题需人工评估，不能自动重写有签名的 EML。生产前仍需解决迁移互斥、单实例运行约束、密钥版本与轮换、备份恢复及真实身份验收缺口。下一阶段仍为 5C 最小管理 API。
