# Phase 8F.5a · 持久模板目录与显式发布

2026-10-08。本阶段把审查后的固定模板版本存入 PostgreSQL，复用既有命令运行账户、辅助进程占用、审计、备份与恢复。发送请求和渲染语法不变；不新增 HTTP 路由或工作台权限。

后续 [8F.5b.1](phase-8f5b1-template-retirement.md) 已补齐逐版本退役，区分八个活跃版本与最多 64 个历史版本；下文限额及“尚无退役”描述保留为本阶段验收时的范围，当前操作请参考后续手册。

## 升级前置

新增 00025_template_catalog.sql。按 9B.1 停止写入，使用数据库 owner 显式执行 `relaytale migrate --offline`，随后按 9B.3 权限手册重新运行 runtime-grants.sql，为新表配置运行账户权限。运行账户不能执行迁移；新旧二进制不能同时运行。数据库迁移也会改变备份 schema 指纹，旧 schema 备份应使用对应版本二进制恢复，再走既有升级流程。

本阶段没有对真实部署运行迁移，只在隔离数据库验收。

## 审查与发布

先用 8F.3 的 template-version 工具生成带 version 的固定对象，用 8F.4 本地预览核对内容，再以有受限运行数据库凭证的运营人员执行：

```sh
relaytale publish-template \
  --api-key-id WEBSITE_CREDENTIAL_UUID \
  --actor operator_name \
  --reason 'reviewed order notification' < order-template-versioned.json

relaytale list-templates --api-key-id WEBSITE_CREDENTIAL_UUID
```

目标必须是现存且启用的 rts_ 网站身份；生产/沙箱由身份绑定，不从模板指定。操作者与原因必填，分别最多 128/256 UTF-8 字节并拒绝控制字符，原因不要含凭证或业务隐私。CLI 的操作者标签用于审计，不替代数据库凭证授权；不允许网站凭证自行发布，尚无管理 HTTP 发布接口。

输入和规范化后的持久定义各最多 32 KiB；JSON 转义可能增加字节数，超限拒绝。必须预先带有正确版本；不在发布时默默分配版本。声明变量排序后保存规范化定义，与内容摘要、完整定义 SHA-256、语言和发布时间一起持久化。列表只返回元数据和审计 ID，不输出正文或变量值。

同一身份、ID、版本重复发布同一个规范化对象返回 replayed=true，不追加第二条发布审计。首次发布先锁身份行，再检查目录并原子写入 TEMPLATE_PUBLISHED 审计和版本；提交失败不能称为发布成功，错误后只能用同一对象重试。审计只记录身份、ID、版本、语言、定义摘要和运营原因，不写模板正文。并发发布由身份锁串行化，发布与对应身份配置同步采用相同的身份锁。

## 显式启用与快照

SEND_API_KEYS 中对应身份增加：

```json
{"use_published_templates": true}
```

这是向既有身份对象添加的字段，不是完整凭证配置。默认 false，仅使用原 templates 配置目录；true 时加载该身份数据库目录，与既有配置模板按 ID/版本合并去重。合并后每身份最多八个版本，超限拒绝启动。每身份持久定义合计最多 64 KiB；一次启动选择加载的持久定义总计最多 64 KiB，另有原配置整体 64 KiB 限制。受限目录不提供无限历史存储。

发布成功不表示进程已经激活新版本。启用字段并重启后，在启动事务中验证源摘要、版本、语言、语法以及 TEMPLATE_PUBLISHED 审计与身份、版本、摘要的关联，并编译不可变快照；审计记录实际载入的目录元数据。运行期间不读可变目录或请求时编译，不改变在途提交语义。客户端提交仍显式指定 ID/version/language，无 latest 或语言回退。

## 不可改写与恢复

数据库行按身份/ID/版本唯一，外键保护网站身份及发布审计，定义长度/JSON 元数据/完整字节摘要有 CHECK 约束。UPDATE 与 DELETE 使用数据库触发器直接拒绝，Down migration 要求显式降级计划，不抹除发布历史。

本阶段没有删除、退役或同版本更新命令。需要停止使用模板时，在配置目录中明确选择仍受支持的版本，或禁用该网站身份；持久目录暂不支持逐版本选择加载。已入队邮件继续用原始存档，目录变化与恢复不重建正文。启用持久目录后，若要保持网站发信但停止加载整个持久目录，可置 false 并重启，按客户端重试窗口保留所需静态版本。不要仅为修改正文重新使用旧版本或原幂等键。

备份保存新表及审计；恢复验证逐条检查完整字节摘要、内容寻址版本、语言、身份类型、发布审计关联和每身份限额。按排序流式检查，每次只解析有界定义，不返回源内容；验证失败保留原恢复启动阻断。无新外部副作用。
