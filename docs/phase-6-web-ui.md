# Phase 6 · Web UI

## 设计与范围

以投递工作台为中心：侧栏导航、邮件列表与事件详情，避免用“成功率”混淆 SMTP 接受与实际送达。主色深海蓝 #183B56，强调蓝 #245AC8，底色雾灰 #F3F6FA，纸面白 #FFFFFF，待确认琥珀 #946200，危险红 #B83A45。正文使用系统中文无衬线，品牌使用 Georgia；等宽字只用于可复制的 ID。左对齐，列表优先，移动端详情转为整页。

```
导航 | 邮件 / Provider / 抑制列表 | 当前对象详情
     | 状态、主题、时间           | 收件人与事件时间线
```

设计复核：不制作与任务无关的统计卡片墙或伪造健康百分比；所有数量有范围说明，UNKNOWN 独立突出。界面中文优先、无外部字体/跟踪/第三方静态依赖。

使用 Go embed + 原生 JavaScript/CSS，保留单二进制交付，不增加前端运行时服务。浏览器使用独立密码账户、短期 HttpOnly 会话与 CSRF 验证，共用管理 API 的角色和业务服务。旧 Bearer API 的权限与来源规则保持独立。

本轮不开放原始 MIME、HTML 或附件预览：全部邮件元数据按文本显示，正文外部资源不会加载。SMTP 账户/HTTP 发信 key 的管理不在当前 5C API 范围，继续使用既有 CLI，不制作不可用设置页面。

## 验收计划

- 登录、退出、过期、错误来源、跨站写入、CSRF、角色与并发版本测试。
- 浏览器完整操作：列表到详情、添加/解除抑制、Provider 配置与凭证轮换、UNKNOWN 受控处置；空状态、失败、移动视口与键盘操作。
- 恶意主题按文本显示，不执行脚本或请求外部资源；密码不写入应用持久存储，长期 API 令牌不进入浏览器。
- 全套 CI、阶段 Git 检查点；不启用真实邮件投递。


## 实现与本地验收

完成邮件列表/详情、收件人、可分页时间线、Provider 配置/健康/配额、抑制与 UNKNOWN 操作，及独立 Web 密码账户、会话/CSRF/来源限制。前端为 Go embed 静态资源；生产无需 Node。新增 Node 依赖仅用于格式和浏览器验证，版本与 lockfile 固定。

Go 全套 `make ci` 在全新隔离 PostgreSQL 通过，集成测试 76.326 秒；覆盖旧管理 API/投递回归及新会话权限测试。UI 格式检查通过。浏览器两条完整流程通过：查询至人工处置、抑制添加/解除、配置/凭证写入、只读拒绝、恶意主题文本隔离、无外部图片请求、移动布局、空状态、503 恢复、键盘关闭与会话过期清屏。桌面、登录、详情、手机截图已人工复核。

本地 Playwright 管理的 Chromium 下载超时，改用本机 Chrome 完成验证；远端 CI 安装固定 Playwright 对应的 Chromium，并运行同一浏览器脚本。

### 验收中发现的问题

早期浏览器 fixture 与普通集成测试复用 public schema，留下待投递合成邮件。随后完整测试的 worker 优先领取了旧邮件，两项 UNKNOWN 测试因此缺少当前尝试，报 no rows。查询确认旧演示邮件已被该轮 worker 处理。修复为每轮浏览器 fixture 创建独立临时 schema、退出时清理；使用全新数据库重跑全套通过。没有清理或修改生产数据。

手机首版表格需要横向滚动，改为带字段标签的纵向记录；详情时间线过长，改为可键盘聚焦的滚动区域。长期管理令牌从未进入浏览器；会话密码哈希配置错误会阻止启动。

### 明确保留的限制

无原文/附件预览、MFA、共享会话或登录审计；账户变更需要重启。短信/邮件通知、完整 Dashboard 全局统计和 SMTP 账户 UI 不在当前管理 API 范围，不制作占位功能。单实例、迁移互斥、主密钥轮换和恢复演练仍是生产前置条件。完整启用/运维说明见 [Web UI 手册](web-ui.md)。
