# Phase 8C.4：存档目录分页核对

`inventory-eml` 现在可以继续核对单日超过 10000 个条目的目录。仍然只读，不修改文件或数据库，不输出删除许可。

```sh
relaytale inventory-eml --date 2026-09-26 --limit 1000
relaytale inventory-eml --date 2026-09-26 --limit 1000 --after-cursor '<上一页 next_after>'
```

游标必须原样传回，并保持相同的存储根目录和日期；它是文件名字节的 URL-safe Base64 编码，避免非常规文件名被 JSON 编码后无法继续。不是授权令牌，也不是文件系统快照。显示路径中的非 UTF-8 字节可能被 JSON 替换，排查时不能把显示路径当作精确文件标识。

每页按原始文件名字节的字典序处理。`truncated=true` 表示还有下一页，`next_after` 是当前页末尾位置；`complete=true` 表示此次枚举中游标之后没有剩余页。空末页返回空游标，应停止，不能据此从头循环。成功的非末页退出码现在也是 0，这是相对 8C.3 的命令行为变化。实际错误返回非零、complete=false 且不发布续页游标；应重试原游标，不使用部分结果推进。

## 资源与一致性

每页以 256 个目录条目为一批遍历，只保留 limit+1 个最小候选名称，再排序返回。内存规模为 O(limit+256)，limit 仍为 1–10000；不能把这个上限理解成整日最多可扫描 10000 个文件。

为避免持久化目录快照，每一页会重新遍历该日目录，CPU 与磁盘枚举成本随目录大小和页数增长。CLI 保持 15 分钟总超时；过大的目录仍可能超时。这是有界内存方案，不是恒定时间分页。

稳定目录能逐页完整覆盖而不重复。并发新增文件如果排在游标之前、或者扫描时发生更名/删除，不能保证覆盖；需要重新从空游标复扫。数据库查询与目录枚举也不在同一个原子快照中，`NO_VISIBLE_REFERENCE_REVIEW` 仍仅表示待核查。

本阶段只解决单日分页。跨日期自动遍历、持久化候选记录、并发安全回收与通用生命周期仍待实现，完整 Phase 8C 尚未核销。

## 验收

单元测试以 600 个反向创建的文件验证跨读取批次分页不重不漏及取消；集成测试覆盖真实数据库引用、多页边界、空末页、非法游标、反斜杠和非 UTF-8 文件名。实际 CLI 已验证两页续扫及非末页退出码 0。重复运行完整 CI 时，发现 8C.3 测试使用固定 `unusual/path.eml` 与上一轮残留记录冲突；改为包含当前消息 UUID 的唯一测试路径，无需清空数据库。修复后在同一数据库上完整 `make ci` 通过，包含格式、vet、build、全量 race 测试；集成测试耗时 96.631 秒。暂存差异检查与离线凭证扫描通过。
