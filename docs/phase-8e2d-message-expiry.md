# Phase 8E.2d · 邮件有效期

2026-10-05。网站可为验证码、重置链接等邮件指定不可延长的投递期限。有效期限制新的发送机会，保留已经接受、明确拒绝和不确定的 SMTP 事实；网关不承诺在期限内送达，验证码的实际有效性仍由网站检查。

## 提交契约

原始 EML 的 HTTP 请求可增加一个 `X-RelayTale-Expires-At: 2026-10-05T16:05:00Z`。这里只展示时间格式，使用时需换成当前未来时间。接受带时区 RFC3339、整秒精度，统一以 UTC 保存；缺省表示无期限。空值、重复头、无时区、非零小数秒及无效时间返回 400 `invalid_expiry`。SMTP 接入不会从 MIME 头读取有效期。

新请求在数据库身份锁内重新判断期限：已经到期返回 410 `expiry_elapsed`，超过未来 720 小时返回 422 `expiry_out_of_range`。判断发生在预算准入及正式归档之前；拒绝不发布 EML、不留下幂等占位、不计费。若准入时尚未过期，随后在归档/提交期间到期，邮件仍可被可靠接受，但不会因此获得过期后的 DATA 授权。

明确的期限参与内部 v4 请求指纹。同一个时刻的时区表示等价；同一个幂等键改变期限返回 409。没有期限的请求保留原 v1/v2/v3 指纹。原请求已经提交后，即使期限已过，同键、同内容、同期限重放仍返回原 message_id，不能通过重放延长期限。授权检查仍适用于重放。

期限及其网站归属由数据库触发器保护，接受后不能修改。原始 MIME、Message-ID 和网站业务字段保持原有内容。

## 过期和发送边界

队列在调度/领取前独立提交有界过期处理，每批最多 20 封。即使 Provider 停用、额度不足或没有可用路线，也可把未发送的 QUEUED/TEMP_FAILED 收件人标为 EXPIRED，清除重试时间并记录逐收件人事件。重复扫描不会重复记录事件或通知。领取查询及更新再次排除过期邮件。

准备 DATA 时，消息锁与现有 suppression 门闩串行化状态。用当前数据库时钟原子选择 `data_armed_at` 或 `expiry_blocked_at`；等待锁期间跨过期限也不能使用事务开始时间绕过检查。数据库约束禁止过期阻断与 DATA 授权/传输证据同时成立，触发器进一步拒绝为已过期邮件写入新的授权。

**期限约束新的 DATA 授权，而非网络发送结束时间。** 已在期限前提交授权的尝试可以在期限后继续，最终结果仍为 SMTP_ACCEPTED、明确 SMTP 拒绝或 DELIVERY_UNKNOWN。它不保证 DATA 命令或远端接受在指定秒数前完成；也不撤回此前已经发出的邮件。

未授权时进程崩溃，租约恢复后可过期；已授权时崩溃仍保守记 UNKNOWN。UNKNOWN 的人工重试在期限过后被拒绝，并保留 UNKNOWN；人工标记已投递/失败仍可用于核对既有事实。期限过后不能把已经授权的尝试强行称作“从未发送”。

Finish 保留 attempt_recipients 中原始 SMTP 结果；例如 RCPT 550 仍是 PERM_FAILED，而同次会话因期限被阻断的待发送收件人变为 EXPIRED。已接受收件人和 UNKNOWN 不会被扫描覆盖。20 收件人邮件若先接受 16 个，再到期，余下 4 个过期，消息汇总仍是 PARTIAL_ACCEPTED。混合永久失败/抑制/过期时沿用汇总规则，需读取逐收件人结果。

EXPIRED 表示不再允许后续尝试，并不证明此前绝对没有投递。若该收件人历史存在 UNKNOWN，之后由操作员显式授权重试，最终又因期限停止，过期决策会保留 `may_have_delivered=true` 及原尝试历史。

新提交预算和已提交的 Provider 尝试额度均不退款。过期拦截本身不是 Provider 故障，不会降低其健康样本；真实上游 4xx 仍按原健康逻辑记录。过期状态的原文可进入既有显式保留/清理流程，事件历史不会被删除；UNKNOWN 的清理限制继续生效，EXPIRED 但仍有 `may_have_delivered=true` 的原文也不会因过期进入清理候选。

## 网站可见性与运行方式

单封状态查询成功响应在 `X-RelayTale-Expires-At` 返回 UTC 期限。状态 JSON v1/v2 字段形状保持，新增 EXPIRED 状态与说明、EXPIRE 决策、EXPIRY_BLOCKED 阶段和 RECIPIENT_EXPIRED / EXPIRY_GATE_BLOCKED 事件；客户端应容忍新增状态/事件。管理消息详情展示 expires_at，Prometheus 保留聚合 EXPIRED 标签。

过期事件通过现有事务 Webhook outbox 捕获，v1/v2 通知字段和签名方式不变。网站收到通知后可查询收件人状态；EXPIRY_GATE_BLOCKED 表示当前尝试被拦截，RECIPIENT_EXPIRED 表示未来发送已停止。不能把两者当成可信异步退信。

状态转换由已启用的 worker 执行。`WORKER_COUNT=0` 或进程停机时，不在后台自动扫过期；状态查询可能仍显示 QUEUED/TEMP_FAILED，但会返回原期限。重新启动 worker 后先处理过期，发送门闩始终检查真实时间，不依赖展示状态已刷新。

## 升级与恢复

迁移 00019 把旧记录视为没有期限；新增列、状态约束和授权保护。升级前停止旧 worker，迁移后统一运行新版本，不支持自动降级删除期限和过期证据。

备份保存期限、过期状态、门闩与通知；恢复校验拒绝 DATA 授权时间不早于期限的矛盾记录。旧版备份应先使用匹配版本恢复，再停 worker 升级。恢复后仍需按 9A 手册核对外部副作用并人工解除启动阻断。

## 验收

定向测试已覆盖时间规范化/指纹兼容、非法/过去/过远期限、同键期限冲突和过期后的重放、数据库不可变性、无 Provider 的重复扫描和事务通知、会话中途过期保留 RCPT 550、授权后接受/UNKNOWN、过期 UNKNOWN 的人工重试拒绝、未授权/已授权租约恢复、16+4 批次部分接受、准入/授权锁等待期间跨过期限、矛盾 Finish 拒绝、事件失败整体回滚、重试时间清理及备份恢复。

验收中，直接写入已过期 DATA 授权的测试曾意外成功。检查发现本地测试库已登记迁移 19，却缺少后来补入的授权触发器：编辑未发布迁移不会让 Goose 在已有库重跑。随后重建本阶段专用 tmpfs 数据库，从空库重新验收最终 schema。这说明重复使用本地测试容器时，新增迁移的后续修改必须在干净数据库上验证，不能只依赖历史版本号和先前通过结果。

最终从空库执行的完整 `make ci` 已通过：格式检查、`go vet ./...`、`go build ./...`、`go test -race -count=1 -timeout=8m ./...`，其中全量集成测试约 212 秒；管理界面脚本语法检查、暂存差异检查和离线敏感信息扫描通过。所有邮件测试使用隔离 PostgreSQL 与 Fake SMTP，未向真实 Provider 或收件人发信。
