# Git 阶段检查点

当前基线包含已完成的 Phase 0 与 Phase 1，首个里程碑为 `phase-1`。此前没有 Git 历史，因此不补造单独的 Phase 0 提交。

后续阶段流程：

1. 从干净的基线创建阶段分支，例如 `phase-2-provider-delivery`。
2. 开发过程中按完整的小功能提交，保留可理解的变更记录。
3. 阶段结束更新文档，运行相关单元、集成和启动检查。
4. 检查暂存差异及敏感文件，提交经过验证的阶段结果。
5. 给阶段结果创建带说明的里程碑标签，例如 `phase-2`。合并时保留可追溯历史。

常用查看命令：

```sh
git status
git log --oneline --decorate --graph --all
git diff phase-1..HEAD
```

需要研究旧版本时优先创建独立工作目录，不覆盖当前工作：

```sh
git worktree add ../mailgate-phase-1 phase-1
```

旧代码运行时不要直接连接当前开发数据库或复用当前数据卷。代码回退不等于数据库迁移回退。

Git 只保存代码与文档。数据库和 EML 需要单独备份，密码与证书也不进入仓库。当前仅建立本地仓库；尚未配置远程备份或推送。
