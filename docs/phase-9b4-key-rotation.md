# Phase 9B.4：Provider 凭证密钥版本与离线轮换

## 范围与兼容性

本阶段只轮换数据库内的 Provider SMTP 密码加密密钥，不修改 SMTP 密码本身，不联网、不投递邮件、不改投递状态。单主密钥配置继续读写原来的 AES-256-GCM 格式。设置 `RELAYTALE_KEYRING` 后，新凭证写入带版本格式；旧凭证必须在环内保留 `legacy` 对应的旧主密钥才能读取。

密钥环只从环境变量读取，例如结构：

```json
{"active":"v2","keys":{"legacy":"<旧的64位十六进制密钥>","v2":"<新的64位十六进制密钥>"}}
```

示例不是可用密钥。使用独立生成的新随机密钥；不得复用旧密钥材料冒充轮换。版本名为 1–64 个字母、数字、下划线或连字符，最多 16 把密钥；`legacy` 不能作为 active。显式空值、重复 JSON 字段、未知字段或无效密钥都拒绝加载，不回退到主密钥。Compose 为此使用可选的环境透传；不要在环境文件里定义空的 `RELAYTALE_KEYRING`。不要把环、命令环境、密码或原始数据库错误贴到日志或工单。

现有 `nonce BYTEA` 存储版本封装：`RTK1 | 版本长度 | 版本名 | 12 字节随机 nonce`。旧格式严格为 12 字节。GCM 附加认证数据同时绑定 Provider ID、格式与版本；读取只选指定版本，不依次尝试其它密钥。不需要数据库迁移，但旧程序不能解密新格式。轮换后不得直接回退到旧二进制，应使用备份恢复计划或继续使用兼容版本。

## 操作步骤

1. 独立保存数据库、EML 与原有密钥的备份。停止服务、采集、维护及其它辅助进程。
2. 在私有环境中配置新环，同时保留所有现存凭证用到的旧版本；`DATABASE_URL` 使用恢复账号，不能使用运行账号。
3. 默认检查：

   ```sh
   relaytale rotate-provider-keys --offline --actor operator --reason planned-rotation
   ```

4. 确认检查成功，再执行同一命令加 `--apply`。Compose 可以通过已有 `recovery` 运维服务运行该命令；覆盖其 command 即可，不需要 EML 参数。
5. 再次默认检查：`changed` 应为 0，`checked` 是所有 Provider 数量。审计事件为 `PROVIDER_KEYS_ROTATED`，仅包含操作者、原因、版本和数量。检查输出的 `source_versions` 可用于判断数据库是否还依赖旧版本；默认模式的 `changed` 表示将更新的数量，`applied=false` 表示未写入。
6. 可在新环境中移除已无数据库引用的旧版本，再运行默认检查；成功后恢复运行。旧备份仍需要旧密钥，必须按备份保留期独立保存，不能据当前数据库无引用就销毁。

命令复用持久离线占用与数据库账号检查，在线服务或辅助进程存在时拒绝执行。所有 Provider（包括停用的）都锁定并逐一认证；已经使用 active 的记录也必须解密成功。全部更新与审计在一个同步提交事务内完成；缺失密钥、损坏密文、审计失败或取消均不会形成已确认的部分成功。重复执行不会重新加密已处于 active 的记录。Provider 配置 revision 会因凭证更新递增，管理端须重新读取。

上限为 10,000 个 Provider，超出拒绝操作，需制定单独的分批与恢复计划。进程崩溃可能保留离线占用，按既有占用恢复流程处理；提交结果不确定时先检查数据库和审计，再运行默认检查，不根据终端报错直接认定没有提交。该功能不提供 KMS、自动轮换或密钥托管；环境与备份访问权限仍由部署方管理。

## 验收

- 完整 `make ci` 通过：格式检查、静态分析、全项目构建及 `go test -race`；隔离 PostgreSQL 集成测试耗时 231.612 秒。
- 最终 JSON 字段大小写修正后再次运行全项目格式、静态分析与构建，并通过密钥格式及真实数据库轮换定向竞态测试。
- 单元测试覆盖旧格式读取、新格式读取、旧程序拒绝新格式、同密钥材料下版本篡改、畸形 nonce，以及无效/空/重复/大小写歧义配置禁止回退。
- 数据库故障注入覆盖缺失旧密钥和审计写入失败；失败后所有 Provider 仍可由旧密钥读取。成功轮换包括停用 Provider，移除旧密钥后读取成功，重复操作不重新加密，错误 active 密钥不能通过检查。
- 实际二进制使用合成角色与 Provider，验证默认检查、实际更新、新密钥单独读取、运行账号拒绝、在线占用拒绝，以及新格式凭证的备份/恢复校验。未连接真实 Provider，未更换生产密钥。
