# Phase 8C：HTTP 发信故障验收与孤立存档回收

8C 将 HTTP 接收的失败恢复和候选原文回收形成闭环。HTTP 发信仍默认关闭；202 仅代表网关持久化接收，不代表收件箱送达。UNKNOWN 不自动重试或清理。新增命令只在操作员调用时运行，不启动后台删除任务。

## 跨日期扫描与候选记录

```sh
relaytale scan-archives --storage-dir data/eml --from 2026-01-01 --to 2026-09-26 --limit 1000
relaytale scan-archives --storage-dir data/eml --from 2026-01-01 --to 2026-09-26 --limit 1000 --record
relaytale scan-archives --storage-dir data/eml --from 2026-01-01 --to 2026-09-26 --limit 1000 --record --cursor '<next_cursor>'
relaytale list-archive-observations --storage-dir data/eml --limit 100
```

默认扫描只读；`--record` 才读取未匹配常规 EML 的摘要并持久化观察证据。每页最多 1–10000 个条目、31 个日期槽；跨度最多 36600 天，稀疏日期会跳过。根目录必须存在；权限、非目录或符号链接等错误会中止。游标绑定根目录、起止日期和 record 模式。直到 complete=true 才到达所选范围末尾；空页可能仍有下一页。

每个候选记录有观察 ID、存档 UUID、根目录、相对路径、大小、SHA-256 和数据库观察时间；不存邮件正文。相同文件内容的重复观察返回同一 ID，错误时不发布下一页游标，重跑同页不会重复计费。观察记录不可更新/删除；入口串行计费最多 100000 条，满额停止记录但仍可只读扫描。单个候选最多 100 MiB，超限保留原文并报错，不静默跳过。

列表使用返回的最后一个观察 ID 作为 `--after-id`，limit 为 1–1000；空列表结束。观察 ID 使用 UUIDv7，但并发新记录不构成列表快照；有并发记录时应复扫核对。年龄达标仅是一个必要条件，不表示可删除。

扫描按标准 YYYY/MM/DD 存档布局及显式日期范围运行；不递归处理布局外手工放置的目录、临时文件或特殊文件。每页仍重新枚举当天目录，内存有界，不保证恒定时间。并发新增/更名可能需要从头复扫，观察记录本身不是文件与数据库的原子快照。

## 预览与显式回收

```sh
relaytale reclaim-archive --storage-dir data/eml --observation-id '<观察 ID>'
relaytale reclaim-archive --storage-dir data/eml --observation-id '<观察 ID>' --actor operator --reason '已核对的孤立原文' --apply
```

默认仅预览，实际回收必须逐条指定 `--apply`、actor、reason。回收要求观察至少经过数据库时间的 24 小时，不提供绕过年龄的命令。应用步骤如下：

1. 校验根目录及规范日期/UUID 路径，拒绝符号链接、非常规条目、超限文件和摘要/大小变化。
2. 获取 messages 表的排他写入保护，等待已有写事务结束；等待超过 2 秒即失败。重新检查所有状态的消息引用，同时检查路径规范化、符号链接/硬链接指向的同一文件。任一引用或无法核实的文件系统错误均拒绝回收。
3. 在同步提交事务中写入不可变退役记录，持久保存存档 ID、观察 ID、操作者、原因与时间。退役 ID 以及文件名对应的 ID 被数据库触发器永久禁止重新入队，包括延迟恢复的 SMTP/API 写入。消息身份写入要求 READ COMMITTED 隔离，其他隔离级别拒绝，避免旧快照绕过退役检查。
4. 只有退役 COMMIT 明确成功后，重新核对文件摘要并删除原文、同步父目录，再写不可变完成记录。

回收采用维护路径，会在引用复核期间短暂阻止 messages 写入；数据库较大时检查所有引用及文件别名可能耗时，应在低流量维护时运行。CLI 总时限仍为 15 分钟。默认预览也需要取得该保护，不是无锁查询。

文件树必须由 RelayTale 独占写入，手工编辑、替换、同步/恢复文件的外部程序必须在回收期间停止。操作系统没有“按摘要条件原子 unlink”的接口；该方案依赖现有 LocalStore 不覆盖已发布 UUID 文件，以及数据库退役保护。管理员绕过触发器、直接修改数据库或外部文件树不在并发安全保证内。

## 失败与恢复

| 故障位置 | 行为 |
| --- | --- |
| 引用检查、内容校验、退役提交回滚 | 不删除原文 |
| 退役已提交但 COMMIT 确认丢失 | 本次不删除；原观察 ID 重试时重新核实并继续 |
| 退役后文件改变 | 保留文件和退役审计，报错，需人工调查 |
| 删除后目录同步或完成记录失败 | 退役保护仍存在；同观察 ID 重试可同步目录并补完成记录 |
| 旧接收任务恢复 | 数据库拒绝退役身份，不能成功确认已删除的原文；客户端可重新提交新请求实例 |

重试不覆盖原始操作者与原因。已有 messages 引用（含 UNKNOWN、终态和策略阻断）一律拒绝作为孤立文件回收；其保留期仍由既有 cleanup 与 Phase 9 生命周期策略管理。

## 迁移与运维

迁移 00013 增加 archive_observations、archive_retirements、archive_reclaims 及保护触发器，全部保留审计历史，Down 明确拒绝自动回滚。不得只恢复 EML 而删除退役记录，也不得绕过退役身份复用 UUID。数据库与文件备份/恢复须一起规划；升级不自动扫描或删除任何现有文件。

跨日期扫描、候选持久化与显式安全回收属于本次 8C 范围。自动定时回收、对象存储、备份演练、数据库容量规划及大规模性能调优仍是 Phase 9，不是 HTTP 发信故障验收的前置条件。

## 验收矩阵

- 8A/8B：并发重复/冲突、身份隔离、撤销/轮换、资源与大小限制、真实本地 TLS 路由。
- 8C.1/8C.2：响应丢失、上传中断、落盘后取消、数据库回滚、真实 COMMIT 成功确认被截断，重试不重复投递。
- HTTP 补充：默认 25 MiB 正文、重放、超一字节拒绝；真实 TCP 上传停滞的读取超时和资源释放。
- 8C.3/8C.4：特殊文件、路径边界、600 文件跨批次分页、非法/非 UTF-8 游标、单日有界扫描。
- 收尾：跨月份与空日期续扫、观察去重和不可变记录、年龄门槛、预览无删除、显式回收及幂等恢复。
- 并发/安全：未提交消息阻止回收、已提交 UNKNOWN 保护、路径别名保护、内容变化与符号链接拒绝、退役后 SMTP/API 延迟写入和不同 ID 路径复用拒绝。
- 故障注入：退役提交回滚、退役提交确认丢失、删除后完成记录失败，均可解释、保留审计并按原观察 ID 恢复。

所有发送均使用隔离 PostgreSQL 与 Fake SMTP，命令验证只处理容器中的合成文件；没有清理真实存档或发送真实邮件。最终版本在全新隔离数据库上通过完整 `make ci`（格式、vet、build、全量 race 测试），集成测试耗时 120.355 秒。实际 CLI 已验证跨日期记录与列表、预览保留文件、显式回收及同观察 ID 重试；暂存差异检查和离线凭证扫描通过。

回归期间发现旧 preflight 测试依赖“所有旧 UUID 排在新 UUIDv7 之前”的隐含假设，已改为独立 schema，避免其他合法 UUID 测试数据干扰。此验收不等同于所有反向代理、WAN、数据库高可用故障组合或生产吞吐验收。
